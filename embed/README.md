# model3d-viewer

Просмотрщик 3D-моделей для веба: STL, 3MF-проекты и нарезанный G-code. Рисует
на WebGL, раскрашивает по филаментам, режет на слои, показывает стол принтера и
навигационный куб. Без React, без сборщика, без зависимостей.

Один скрипт и один тег:

```html
<script src="dist/model3d-viewer.js"></script>
<model3d-viewer src="./деталь.3mf" language="ru" style="height: 480px"></model3d-viewer>
```

Или из кода, если нужен контроль над жизненным циклом:

```js
import { mount } from './model3d-viewer.mjs';

const panel = mount(document.querySelector('#box'), {
  source: './деталь.3mf',
  language: 'ru',
});

panel.dispose();   // освобождает GPU-контекст
```

## Что он умеет

| | |
|---|---|
| Форматы | `.stl` (двоичный и ASCII), `.3mf` (включая встроенный G-code), `.gcode` |
| Раскраска | по филаментам проекта, с перекраской любого слота |
| Виды | модель / нарезка, переключаются, если в файле есть и то и другое |
| Слои | ползунок с двумя границами, режим одного слоя, затемнение нижних |
| Стол | сетка по `printable_area` из файла, с осями |
| Куб | 26 областей, клик — вид, перетаскивание — вращение камеры |
| Материал | матовость, металличность, прозрачность — отдельно каждому филаменту |
| Свет | студийный или простой, общий уровень |
| Экспорт | PNG в 2048 px по кнопке; отдельно — трассированный кадр |
| Трассировка | трассировка лучей с тенями, AO и двумя отскоками по кнопке |

Управление: ЛКМ — вращение, ПКМ или Shift+ЛКМ — сдвиг, колесо — масштаб.

## Доступ

### `mount(host, options)`

Создаёт панель в элементе и возвращает её. Опции:

| Опция | По умолчанию | Смысл |
|---|---|---|
| `source` | — | URL, `File`/`Blob`, `ArrayBuffer`/`Uint8Array`, `{name, url}`, `{name, bytes}`, `{name, blob}` или функция, возвращающая любое из этого |
| `language` | английский | `en`, `ru` или любой тег; `ru-RU` тоже подойдёт |
| `t` | — | свой переводчик `(key, params) => string`, вместо встроенных словарей |
| `locales` | встроенные | свои словари `{en: {...}, ru: {...}}` |
| `view` | `auto` | `auto`, `model` или `sliced` |
| `fileName` | из источника | имя в строке статистики |
| `showName` | `false` | показывать имя в строке статистики |
| `requestInit` | — | передаётся в `fetch` |
| `signal` | — | `AbortSignal` хоста |
| `onStatus` | — | `({kind, message?, mesh?, sliced?, name?})`, `kind` — `ready` или `failed` |
| `remember` | `true` | помнить настройки этого файла: `true`, `false` или своё хранилище |
| `storageKey` | из источника | явный ключ, если источник его не даёт |

Методы панели: `setView`, `setLayers`, `toggleOneLayer`, `toggleBed`,
`togglePlainLighting`, `setSurface`, `setLightLevel`, `setFilament`,
`setBackground`, `setOrbit`, `reset`, `saveImage`, `dispose`.

### `<model3d-viewer>`

Атрибуты: `src`, `language`, `view`, `name`. События: `model3d-status` и
`model3d-ready`, оба несут `detail` с тем же объектом, что и `onStatus`.

Если источнику не хватает атрибутов — скажем, это байты в памяти или свой
транспорт, — задайте `element.source` до вставки в документ.

### Движок отдельно

Если нужны свои органы управления, берите движок без панели:

```js
import { parseModel, createViewer } from './model3d-viewer.mjs';

const parsed = parseModel('деталь.3mf', bytes);
const viewer = createViewer(canvas);
viewer.setMesh(parsed.sliced ?? parsed.mesh);
viewer.setOrbit(0, Math.PI / 4);
```

Экспортируется также `parseStl`, `parse3mf`, `parseGcode`, `createCube`,
`formatSize`, `BACKGROUNDS` и `ViewerPanel`.

## Настройки запоминаются для каждого файла

Просмотрщик помнит, как вы смотрели **этот** файл: режим света, стол, фон,
камеру, материал и цвета каждой нити, диапазон слоёв. Открыли снова — всё на
месте.

Это суждение о конкретной печати, а не о программе: чёрная крышка смотрится
матовой, яркая наклейка — глянцевой, одна пластина читается на тёмном фоне,
другая на светлом. Сбрасывать это при каждом закрытии вкладки значит заставлять
человека принимать одни и те же решения заново.

```js
mount(box, { source: './деталь.3mf' });                    // помнит (localStorage)
mount(box, { source: './деталь.3mf', remember: false });   // всегда с чистого листа
mount(box, { source: './деталь.3mf', storageKey: 'проект-42' }); // свой ключ
```

Ключ — это личность файла, и от неё зависит, не перепутаются ли настройки:

| Источник | Ключ |
|---|---|
| URL | путь целиком: два файла с одинаковым именем в разных папках — разные файлы |
| `File` | имя + размер + время изменения |
| байты без имени | ключа нет — **запоминание выключается**, а не угадывается |
| `storageKey` | всегда главнее |

Выключить запоминание для источника без личности — сознательное решение: общий
ключ применил бы материал одной модели к другой, а это хуже, чем забыть.

**Кнопка сброса забывает, а не запоминает.** Иначе единственный способ отменить
свои изменения молча не отменял бы те, что сохраняются.

Устройство — в `src/persist.js`. Три вещи, из-за которых такое обычно становится
помехой, и как они закрыты:

- **Сломанное хранилище не ломает просмотрщик.** `localStorage` бросает
  исключение в приватном режиме и при переполнении; каждое обращение обёрнуто, а
  неудача означает «ничего не помню», а не ошибку.
- **Старым данным не доверяют.** Хранимое версионировано, каждое поле
  проверяется; незнакомое отбрасывается, а не чинится в похожее.
- **Запись не на каждый кадр.** Вращение меняет состояние на каждом движении
  мыши, а запись синхронная. Сохранение отложено и сбрасывается при закрытии.

## Трассировка лучей

Кнопка с лучом включает трассировку: камера замирает, кадр набирается по
сэмплу за кадр и проявляется на глазах. Счётчик в строке состояния показывает,
сколько набрано.

Что это даёт, чего растеризатор не умеет:

| | Растр | Трассировка |
|---|---|---|
| Мягкая падающая тень | нет | да |
| Контактное затемнение в щелях | нет | да |
| Отражение модели в себе | нет | да |
| Силуэт по точной геометрии | да | да |

Проверено численно: на модели 42% поверхности заметно темнее растра, средняя
яркость 75 → 57 — это и есть найденная окклюзия, а не общее затемнение.

Экспорт трассированного кадра — отдельная кнопка. Это не снимок экрана: камера
та же, но кадр считается заново на своём offscreen-трассировщике, в 1024 px и
160 сэмплов, с тем же фильтром. Скриншот был бы кадром в процессе набора и в
разрешении панели.

Считается частями: по четыре сэмпла за оборот событийного цикла. Одним циклом
вкладка замирала на шесть с половиной секунд и прогресс не мог отрисоваться.
Нарезки мало — вызов WebGL только ставит работу в очередь, и без синхронизации
в конце слайса вся стоимость сливалась в финальный readback одним стопором в
4.6 с. С ней самый долгий стопор — 0.37 с в цикле и 0.63 с на денайзер с
кодированием PNG.

Для тех, кому нужен просто кадр, есть блокирующая `renderStillToDataUrl`; она
крутит тот же `createStillRender` в цикле, поэтому два пути не расходятся.

| | |
|---|---|
| Ускоряющая структура | BVH, binned SAH по широкой оси (12 корзин) |
| 4 420 треугольников | 2 889 узлов, 110 мс |
| сотни тысяч штрихов | ~100 тысяч узлов, доли секунды, единицы МБ |
| Сэмплов по умолчанию | 96 (экспорт — 160) |
| Накопление | `RGBA16F` с аддитивным блендингом |
| Денайзер | 3 прохода joint-bilateral по нормали и глубине |
| Отскоков | 2 |
| Экспорт | слайсы по 4 сэмпла, синхронизация в конце каждого |

Штрихи трассируются как **капсулы** — аналитическое пересечение, дешевле
треугольников. Модель — как треугольники.

### Чего трассировка не делает

- **Два отскока, без многократного GI.** Отражение освещается своим светом и
  своей тенью, но свет, отражённый дважды, не собирается.
- **Денайзер пространственный, а не обученный.** Три билатеральных прохода
  убирают зерно, но не восстанавливают то, чего в кадре нет. Честный выигрыш —
  около 2× по шуму: 1 сэмпл с фильтром выглядит как 2 без него.
- **Капсула круглого сечения.** У штриха высота и ширина различаются на доли
  процента при слое 0.2 мм, и второй радиус не хранится.
- **Нужен WebGL2** и `EXT_color_buffer_float`; иначе кнопка честно говорит, что
  недоступна.

### Что было не так с самой панелью

Пять дефектов, каждый из которых выглядел как осознанный минимализм и ни один не
бросал исключения:

- **Кнопки трассировки были без иконок.** `icon()` возвращает `null` для
  неизвестного имени, а `trace` и `saveTraced` в наборе не было. Кнопка с пустым
  содержимым — невидимая кнопка; вы её просто не видели.
- **Подписи слайдеров были пустыми.** `applySettings()` выходил рано, если
  сохранённых настроек нет, и пропускал синхронизацию в конце. А нет их при
  первом открытии файла — то есть всегда, когда это заметно.
- **Слайдеры правили не то, что на экране.** Панель хранила свой список
  материалов филаментов и никогда не заполняла его из сцены: перетаскивание
  начинало с дефолта, а не с текущего значения.
- **Кнопка сброса была отключена навсегда.** Флаг загрузки ставился и никогда не
  снимался, а кнопка отключена, пока он стоит.
- **Четвёртый слайдер уезжал за край.** Строка прокручивалась вбок со скрытым
  скроллбаром, так что «СВЕТ» просто отсутствовал без всякого признака.

Теперь строка переносится, подписи заполняются, состояние берётся из сцены, а
`panel-check.html` проверяет всё это на ширине 400 px — сайдбара, а не окна.

### Два бага на стыке двух конвейеров

Оба проявлялись одинаково: «пока не переключишь вид — всё нормально».

**Палитра не доезжала до движка при открытии файла.** `syncPalette()` обновляла
только свотчи в панели; геометрию красит `setPalette`, а он вызывался лишь при
редактировании цвета. Поэтому модель открывалась с пустой палитрой, и поход в
нарезку «чинил» её побочным эффектом.

**Дивизор вершинных атрибутов протекал через границу конвейеров.**
`vertexAttribDivisor` живёт на индексе атрибута, а не на программе, и оба
конвейера делят индексы по раскладке. Конвейер штрихов ставит `divisor = 1` для
инстансных атрибутов; конвейер треугольников их не сбрасывал. Модель, нарисованная
после плиты, читала один цвет на **треугольник** вместо вершины — верхняя крышка
возвращалась плоской заливкой. Замерено в оттенках: 52 → 4.

Лечится сбросом дивизора на каждой отрисовке треугольников — дёшево и не может
снова разъехаться.

### Почему счётчик мог убежать за бюджет

Лечилось не там, где выглядело. Проход по штрихам ставился двумя способами сразу:
кадровый колбэк **и** сторожевой таймер на 100 мс. Кто первый срабатывал, тот
трассировал проход; но проигравший **не отменялся**. На плите, где проход дольше
100 мс, таймер выигрывал всегда, а брошенный кадровый колбэк через мгновение
запускал рядом вторую цепочку проходов. Две становились четырьмя, четыре —
восемью, счётчик уходил за 96, вкладка замирала.

Замерено на настоящем файле: **111 сэмплов** при бюджете 96. Лечится
одним флагом — проход захватывает работу и отменяет соперника, — а не удлинением
сторожа. Удлинить его было первым, что я попробовал; это спрятало бы симптом и
замедлило любую страницу без кадров в десять раз.

## Сборка

```bash
node embed/build.mjs      # -> embed/dist/model3d-viewer.mjs и .js
node build.mjs            # -> client.js, половина для DSH
node verify/library.mjs   # проверка в браузере
```

Сборщика нет и не нужно: десять модулей с фиксированным порядком
склеиваются, а `export`/`import` из них вырезаются.

**Порядок модулей — это граф зависимостей**, потому что после склейки всё
лежит в одной области видимости. Два объявления с одним именем тихо
переопределяют друг друга. Однажды помощник куба переопределил компилятор
шейдеров модели, и ошибки шейдера модели приходили как ошибки куба.

## Что проверено и чего проверка не ловит

Проверено в настоящем браузере (headless Chrome, WebGL через ANGLE Metal):
18 прогонов, 28 вызовов API, пиксельные утверждения на скриншотах. Отдельно
проверено, что настройки переживают пересоздание панели (25 утверждений) и что
сброс их действительно стирает. Трассировка проверяется дважды: что кадр
набирается и темнеет от теней, и что выгруженный PNG действительно содержит
изображение, а не пустоту.
Скриншоты **побитово воспроизводимы** между запусками, поэтому пороги имеют
смысл.

Проверки, которым нужны настоящие 3MF и G-code, **пропускаются**, если этих
файлов нет (они не в репозитории): `node verify/fixtures.mjs` подкладывает их,
когда рядом есть папка с напечатанными файлами.

Не проверено: реальные жесты мышью и тачпадом. Скриншот показывает
результат, но не то, что перетаскивание ощущается правильно.

## Ограничения

- Прозрачность рисуется без сортировки по глубине.
- Обычный PNG-экспорт — растеризация того же кадра. Трассированный выгружается
  отдельной кнопкой и считается заново.
- Цвета модели записаны в каждом треугольнике; перекраска влияет только на
  нарезку.
- Куб рисуется только вместе со столом.
- Фон PNG всегда непрозрачный.
- Один и тот же файл в разных вкладках читается и разбирается заново.

`locale/en.json` и `locale/ru.json`, по 38 плоских ключей. Словари
встраиваются в сборку, поэтому `language="ru"` работает без лишних запросов.
